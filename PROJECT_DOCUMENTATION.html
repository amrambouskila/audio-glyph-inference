Overview — what this is & why

A system-identification / operator-inference problem dressed as a Hebrew calligraphy toy: given audio in, glyph geometry out, find the simplest explicit operator that connects them.

The project asks a single, unusual research question. Given paired examples (x_i, L_i) of (spoken-letter audio, canonical glyph contour), is there a compact, interpretable, mathematically explicit transformation F_θ : x(t) → G that maps the audio waveform directly to the 2D glyph shape? The unknown object is the algorithm itself — a constrained parameter vector θ over an interpretable family (Fourier series, Lissajous curve, phase-space embedding, driven ODE, symbolic expression), not a black-box net and not a letter label.

The core constraint
The unknown is the transformation. The label is known at training time (it selects the target glyph L_i); the question is whether an explicit operator generalizes across accents. Whenever a change is tempted to "just make a letter look right," that is the exact failure mode the project is designed to avoid. A lookup-table-disguised-as-math is a bug, not a solution. See CLAUDE.md §0.

What it is NOT: not a classifier (phoneme → label); not a generative model (GAN/diffusion/latent → pixels) as the main solution; not a decorative visualization pipeline; not a phoneme → glyph lookup table. Neural nets are acceptable only as candidate proposers whose output is distilled into explicit symbolic math.

The fit is the regularized minimization

where d(·,·) is a shape distance (Procrustes by default), λ weights a complexity/MDL penalty, and the headline generalization test is leave-one-accent-out: a single speaker records each letter in five Hebrew pronunciation traditions, the operator is fitted on four accents, and it must produce the correct glyph geometry for the fifth. Negative results are an explicitly valid outcome — if no family generalizes, the project reports that with the search transcript.

Core modules & engines

The heart of the system. Each engine is standalone and importable in isolation. Drill into any one below.

AudioPreprocessor — raw recording → validated framed signal simulation/audio_preprocessor.py

Turns a user-uploaded .m4a into a clean, normalized, framed NumPy matrix. The pipeline (per docs/recording_protocol.md §3/§7) is: decode → validate duration ∈ [1, 3] s → reject if peak > −1 dBFS (clipped) → resample to 16 kHz → loudness-normalize to −23 LUFS (pyloudnorm / ITU-R BS.1770) → VAD-trim silence → validate active-speech span → frame with librosa.util.frame, clipped to [-1, 1]. Rejections raise AudioValidationError; thresholds come entirely from config, never hard-coded.

backend/src/simulation/audio_preprocessor.pydecode / preprocess / load.
backend/src/simulation/preprocess_result.pyPreprocessResult dataclass-style return (frames + native rate + duration + peak).
backend/src/simulation/audio_validation_error.pyRaised on any out-of-spec recording.
Reconstruct, don't store
Only the raw .m4a is persisted (Decision #10). The preprocessed signal is regenerated on demand — there is no .wav sidecar and no wav_path field. The experiments router rebuilds frames from the file path at search time.
GlyphExtractor — STAM font glyph → ordered contour list simulation/glyph_extractor.py

Renders a Hebrew glyph form from StamAshkenazCLM.ttf with freetype-py, traces every external stroke with OpenCV (RETR_EXTERNAL, ordered largest-area first), resamples each closed contour by arc length (points allocated by perimeter share of a fixed budget), then jointly centers on the combined centroid, flips to y-up, and scales into the unit square [-0.5, 0.5]. An empirical 22-letter sweep showed 20 letters are single-stroke and ה / ק have a detached stroke; "largest contour only" would drop ~18% / ~29% of the ink, so the extractor returns an ordered list of contours (Decision #5 = Option C) and GlyphTarget carries num_contours.

backend/src/simulation/glyph_extractor.pyrender → external contours → resample-by-perimeter → joint normalize.
backend/src/simulation/contour_resample.pyresample_closed — arc-length-uniform closed resampling (shared with families).
backend/src/simulation/contour_normalize.pynormalize_to_unit_square — centroid-center + 0.5/max-abs.
backend/src/simulation/contour_io.pysave_contours / load_contours — the ordered .npz on disk.
shape_distance — d(F_θ(x), L) simulation/shape_distance.py

The three metrics in the objective, all taking two (N, 2) float64 unit-square contours and returning a non-negative float (lower better, 0 = identical). Procrustes is the default fitness: full-Procrustes disparity after optimal similarity alignment (translation/scale/rotation invariant), with reflection disabled because Hebrew letters are chiral; it returns 1 - trace². Chamfer is symmetric mean nearest-neighbour distance via cKDTree, normalized by the unit-square diagonal SQRT2. Fréchet is discrete Eiter–Mannila DP minimized over cyclic start-shifts + winding reversal so it measures shape not parameterization phase. Chamfer/Fréchet are tiebreakers; never compare contours with ==.

backend/src/simulation/shape_distance.pyprocrustes / chamfer / frechet free functions.
backend/src/simulation/contour_compare.pyDispatches the three by metric name — the single helper engine + /api/inference share.
backend/src/simulation/batch_procrustes.pyVectorized batched Procrustes/Chamfer over (B, N, 2) for the search hot loop.
TransformFamily protocol + the family zoo simulation/transforms/

Every F_θ family implements one sacred protocol: name(), parameter_space() → dict[str, ParameterSpec], complexity(theta) → float, and forward(audio, theta) → (N, 2) float64 in the unit square. Families are stateless except for their type — all config (sample rate, raster size, point count) comes from BackendSettings, not from __init__.

Two-tier θ (the anti-lookup design)
For Fourier/Lissajous, θ has a searched tier (declared in parameter_space(), e.g. rank_r, ridge_alpha) and a fitted tier (affine vectors produced by a closed-form ridge least-squares in SearchEngine, carried as list[float]). The coefficients come from a rank-r affine map of the audio feature vector φ: coeffs = U·(Vᵀφ) + b. Low rank caps capacity so the operator structurally cannot memorize 22 letters as a soft lookup — the critique that flagged the original "affine ⇒ Lipschitz ⇒ not a lookup" reasoning as a disguised lookup is why this exists. See docs/phases/phase-2-plan.md §3.1/§5.
FamilyPhaseIdeaFile
fourier_series2Closed trig polynomial; 4K coefficients from a rank-r affine map of φ.fourier_series.py
lissajous2Coupled sinusoids, integer ratios (global), linear P·sin+Q·cos drivers from a small affine of φ.lissajous.py

The Fourier forward() re-extracts φ from audio, reshapes the fitted affine vectors, applies U·(Vᵀφ) + b to get 4K coefficients, synthesizes a closed contour, and normalizes to the unit square — a pure function of (audio, θ) and config.

The dynamical-system family drives a second-order ODE with the reconstructed audio signal and integrates with a Numba RK4 hot path (excluded from line tracing because compiled bodies can't be traced; covered by behavioral + closed-form harmonic-oscillator tests).

SearchEngine — θ* = argmin mean d + λ·Complexity simulation/search_engine.py

The standalone optimizer. fit(audio, targets, letters, accents, *, shared_across_letters, seed) precomputes the feature matrix φ once, then runs one of four strategies over the ParameterSpec search space, fits the closed-form affine θ for fittable families, scores candidates with batched Procrustes/Chamfer (Chamfer-substituting for multi-stroke ה/ק), records the anti-lookup lookup_ratio, and returns TransformCandidates sorted best-first.

StrategyMechanism
gridCartesian product of per-axis grids; for Fourier, also sweeps K=1..k_max. Fails loud or seeded-shuffles when it exceeds max_evaluations.
cma-espycma over a normalized [0,1]^dim genotype; continuous-only (rejects categorical/integer axes).
bayesianDeterministic Gaussian-process / expected-improvement over the same genotype decoder; mixed continuous/integer/categorical via _decode. NumPy + SciPy normal CDF only.
symbolic-regressionDelegates to symbolic_search.fit_symbolic_regression (optional PySR proposal path); requires SymbolicRegressionFamily.

The objective adds the regularizer with a sharing multiplier that penalizes per-letter tuning — a single shared θ that works for all letters is structurally preferred over 22 letter-specific θ's.

Audio features φ — the anti-lookup feature vector simulation/audio_features.py

extract_features maps framed audio to φ ∈ ℝ²⁴ = [log-mel means | global spectral descriptors | per-time-third descriptors], pure NumPy. It is deliberately transient-retaining (per-segment descriptors) so φ is not a clean phoneme label — that would make the audio→glyph map a disguised lookup. Dimensionality is config-driven: D = feature_n_mels + 4 + 4·feature_n_segments (default 8 + 4 + 12 = 24). Short live windows reuse the nearest frame so per-segment descriptors stay finite.

backend/src/simulation/audio_features.pyextract_features → φ.
Anti-lookup diagnostics — lookup_ratio & FeasibilityProbe simulation/lookup_ratio.py · feasibility_probe.py

lookup_ratio is the standing anti-lookup diagnostic: after reflection-disabled similarity alignment, it computes within-letter variance / between-letter variance of the generated contours. Near 0 means the operator emits a per-letter constant (a lookup); inf means no between-letter variance. The FeasibilityProbe is the closed-form gate run before committing full search compute: it ridge-fits the affine-Fourier map on the non-held-out accents, scores the held-out accent against the probe and against per-letter / global constant baselines, and classifies the result.

Key logic & formulas

The math that carries the research question, in plain language and tied to code.

1 · The fit

For a family F_θ, a dataset slice, a shape distance d, and a complexity regularizer, the search minimizes θ* = argmin_θ Σ d(F_θ(x_i), L_i) + λ·Complexity(F_θ). The sum is over the training slice; λ is config-set (regularization_weight), never hard-coded; Complexity is the family's declared MDL-style penalty. Implemented in search_engine.py.

4 · Shape distances

MetricPropertiesRole
procrustes_distanceFull-Procrustes after similarity alignment; reflection disabled (chiral); returns 1 − trace².Default fitness.
chamfer_distanceSymmetric mean NN distance (cKDTree), SQRT2-normalized.Sampling-robustness tiebreaker + multi-stroke substitute.
frechet_distanceDiscrete Fréchet over cyclic shifts + reversal, SQRT2-normalized.Stroke-order tiebreaker (report-only).

5 · The anti-lookup ratio

Computed after reflection-disabled similarity alignment of the generated contours: lookup_ratio = mean_letter( Var_within ) / Var_between. A small ratio means the operator produces a near-constant contour per letter — i.e. it has degenerated into a lookup table — which the feasibility probe flags as TRIVIAL_LOOKUP. This is the single most important guardrail against the project's stated failure mode. Implemented in lookup_ratio.py.

How to run it

Docker is the primary path; a backend-only no-Docker loop exists for TDD. See docs/run_guide.md.

Docker (primary)

  1. Copy .env.example to .env (defaults work out of the box).
  2. Run run_audio_glyph_inference.sh (macOS/Linux) or run_audio_glyph_inference.bat (Windows).
  3. The launcher runs docker compose up --build -d, polls /health until ready, prints the URLs, and enters the [k]/[q]/[v]/[r] loop.
  4. Open the frontend at http://localhost:5220; API docs at http://localhost:8220/docs.
[r]
Full restart — down then up --build (keeps images). Repeatable.
[k]
Stop, keep images (terminal).
[q]
Stop + remove project images, keep volumes (terminal).
[v]
Stop + remove images + volumes (terminal).

Backend only (no Docker)

How to edit & extend it

Practical, owner-focused recipes. Always start a session by reading CLAUDE.md → master plan → status.md → the current phase plan, then the files you'll touch.

Add a new transform family F_θ

The most common extension. Use /new-transform-family to scaffold, then:

  1. Create backend/src/simulation/transforms/<family>.py implementing the four protocol methods (name, parameter_space, complexity, forward). forward must return (N, 2) float64 in [-0.5, 0.5] and be a pure function of (audio, theta) + config — no globals, no I/O, no unseeded RNG.
  2. Register it in family_registry.py (FAMILY_REGISTRY).
  3. If it needs closed-form fitting, also implement FittableFamily.fit_theta and a batched synthesizer; otherwise SearchEngine._generate falls back to per-sample forward.
  4. Add an interpretability prior in SearchEngine._family_prior + a config knob (default 1.0).
  5. Declare every searched θ key in parameter_space() as a ParameterSpec; declare config-driven tunables in config.py — never hard-code numbers.
  6. Add backend/tests/simulation/transforms/test_<family>.py with at least one reference-value test (a closed-form input with a known output) — a test that asserts the engine equals the engine is not a test.
Pattern to copy
Use dynamical_system.py as the template for a non-fittable family (categorical mode + continuous knobs) and fourier_series.py for a fittable affine family.
Add a new dataset / experiment API endpoint
  1. Add the handler to the matching router under backend/src/api/routers/ (or a new router + include it in main.py).
  2. Inject dependencies via dependencies.py (session, settings, preprocessor, extractor, tracker) — never construct engines inline.
  3. Validate at the boundary (letter/accent/variant membership, MIME, size, path-traversal); trust types internally.
  4. Convert ORM → Pydantic with Model.model_validate(row) for responses.
  5. Add real-Postgres integration tests in backend/tests/api/routers/.
Change a data contract (the careful path)
  1. Flag the change to the maintainer first — it's a (major) semver bump.
  2. Update master plan §3, then the Pydantic model, then the ORM row, then a new Alembic migration under backend/migrations/versions/.
  3. Mirror the field in apiModels.ts.
  4. Update the contract-check skills and tests. The contract-check / data-driven-check skills enforce alignment.
Edit the live UI behavior

The live workspace is mostly in App.tsx (connection/mic lifecycle), the R3F overlay in LiveCanvas.tsx, and the dashboard in ScoreChart.tsx. Wire-format changes go in liveMessages.ts (frontend) and live.py (backend) — they must stay in lockstep. Keep charts behind their components (a Chart.js → WebGL swap should touch only the chart files). Vitest does not auto-cleanup; tests/setup.ts handles it.

Hands off git
The maintainer manages all git state. Agents never run git add/commit/push/checkout/... — only read-only git. When work is done, report changed files + a suggested commit message; do not commit.

Domain glossary

Terms a newcomer needs to read the code and docs.

F_θ
The unknown transformation — an explicit operator mapping audio waveform x(t) to a 2D glyph contour G, parameterized by θ. The whole project is about recovering it.
θ (theta)
The fitted parameter vector. Two tiers: searched (declared in parameter_space()) and fitted (closed-form affine vectors).
Transform family
A parameterized class of operators (Fourier, Lissajous, phase-space, dynamical, symbolic) implementing the TransformFamily protocol.
Glyph form
A written Hebrew letter shape: 22 regular + 5 sofit (final) forms ך ם ן ף ץ = 27. Sofit forms are glyph targets only, not separate audio labels.
Audio form
A spoken (letter, pronunciation_variant) pair: 28 total — begadkefat letters get hard/soft, the rest plain.
Accent
A Hebrew pronunciation tradition: ashkenazi / sephardi / moroccan / yemenite / chabad. The primary generalization axis.
Leave-one-accent-out (LOAO)
The headline test: fit on 4 accents, hold out the 5th, repeat for all 5. A candidate that only works on its training accent is an overfit, not a discovery.
Procrustes distance
Shape distance after optimal similarity alignment (reflection disabled — letters are chiral). The default fitness.
Lookup ratio
Var_within / Var_between of generated contours; the anti-lookup diagnostic. Small ⇒ degenerate per-letter constant (a lookup).
Feasibility probe
A cheap closed-form gate (FEASIBLE / TRIVIAL_LOOKUP / NO_FIT) run before spending full search compute.
STAM
The canonical Torah-scribal Hebrew script style. Targets render from StamAshkenazCLM.ttf (Culmus, GPL v2).
Complexity / MDL
The regularizer term λ·Complexity(F_θ) — an MDL-style parameter cost favouring simpler operators.
Stage 7
The data-collection step: 700 real .m4a recordings that unblock every empirical gate.
